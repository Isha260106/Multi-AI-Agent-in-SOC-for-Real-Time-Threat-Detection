# Alert Correlation Agent

**Multi-Agent SOC Project | Stage 7**

## 1. Purpose
The **Alert Correlation Agent** provides a rule-based engine to intelligently group corresponding security alerts fired by independent Multi-Agent modules relating to the same foundational event.

## 2. Alerts versus Incidents
- **Alert:** An isolated finding raised by one specific detection agent reflecting local suspicion over anomalous or recognized traits.
- **Incident:** A consolidated, escalated threat-record aggregating multiple individual alerts representing the full attack footprint on a single target origin. 

## 3. Correlation Rules
This stage focuses exclusively on rule-based associations rooted strictly across the `event_id`.
1. **Multi-Alert Grouping:** If two or more independent alerts correspond to the exact same `event_id`, they are merged into a single multi-agent incident.
2. **Missing Correlatives:** If an event generated only a single alert by one agent, the original alert remains preserved but an incident is not created. (A threat isn't escalated manually unless the designed multi-layer sensors form consensus or the standalone pipeline escalates it independently).
3. **Idempotency:** Re-processing the exact same sequences generates duplicate Incident UUIDs using consistent `uuid5` schemas mapped off sorted sub-alert IDs. The SQLite backend gracefully forces `INSERT OR IGNORE` upon these structures to prevent phantom escalations.

## 4. Severity Logic
Incident severities summarize consensus:
- **HIGH:** If two alerts flag an event with `HIGH` severity.
- **MEDIUM:** If only one detecting agent triggers a `HIGH` suspicion severity while the secondary sensor measures normal traffic flow bounds (or if one flags `MEDIUM` alongside `LOW`).
- **LOW:** Event recognized universally as `Normal` across sensory inputs.

## 5. Input & Output Formatting

**Input Example:**
```python
agent = AlertCorrelationAgent()
alerts_list = [{"alert_id": "...", "event_id": "999", "severity": "HIGH", "agent": "Network Detection Agent"}]
incidents = agent.correlate(alerts_list)
```

**Output Example:**

## 7. Limitations
- **Current correlation is rule-based.** It acts entirely passively relying upon strict ID linkages generated by upstream Producers.
- It does not perform advanced temporal attack-chain analysis (tracking threats extending across multiple IP sequences or differing distinct temporal frames).
- It does not build an investigative attack graph.
- It does not offer LLM-assisted context/investigation natively.
- It is solely an aggregator mapping SOC pipelines for lab-scale monitoring without autonomous active-response automation/blocking.

## 8. Future Improvements
Subsequent SOC expansions may integrate real-time ML-driven pattern grouping, threat-intelligence lookup enrichment engines to confirm foreign actors, or LLM mapping algorithms linking chronological graphs mapping true autonomous root-cause investigation mechanisms.
